おすすめ · この画面のサンプルもこの作り方
① 動画にして歩かせる
側面の立ち絵を1枚だけ用意して、それを動画にします。歩幅も接地も、動画のほうが勝手にそろいます。あとは1周期ぶんを切り出すだけです。


ゲーム用のスプライトを作ってください。

【最初に書き換えるところ】ここだけ変えれば、下の本文にそのまま効きます
【設定画】　<ここにパス>
【動き】　　歩行
【コマ数】　24　← 1周期を何枚にするか（軽くしたいなら12、なめらかにしたいなら32。「動画のまま全部」も可。上限64）
【fps】　　 24
【背景色】　#6E6E6E（中性グレー）　← グリーンバックなら #00FF00。ドット化のときは「背景」を「グリーンバック等」に
【保存先】　<ここにフォルダ>

本文中の【 】は、上の値のことです。

【守ってほしいこと】
1. キャラクターの見た目を文章で書き起こさないでください。【設定画】の画像そのものを
   参照として渡してください。言葉に落とすと別人になります。
2. 背景は【背景色】で統一してください。白やクリームだと、モデルが
   地面の影を描き、透過したあとに足元へ白い楕円として残ります。
3. 途中の判断は、必ず画像を見せて確認を取ってから次へ進んでください。
4. 出力するコマは【コマ数】枚です。確認用の画像のために枚数を減らさないでください。

【手順】
① 【設定画】から側面の立ち絵を1枚用意する
   - 設定画が三面図なら、側面だけを切り出す
   - 検出した人物を全部並べて番号を振り、どれが側面かを私に見せて確認してから使う
     （正面・側面・背面＋バストアップの4枚組だと、幅で選ぶと側面が落ちます）
   - 切り出したあと、頭のてっぺんが平らに切れていないか確認する
     （頭頂は本来1〜10pxに細ります。40px以上あれば切れています）
   - 小道具（槍・杖・旗など）は、先端が頭より高くならないようにする
     高いと、全体の高さで揃えたときに体だけ小さく見えます

② 立ち絵を【動き】の動画にする（i2v）
   - 被写体はキャンバスの高さの60%程度。上下左右に余白を取る
   - プロンプトには「真横・一定の速さ・カメラは動かない・背景は平らな【背景色】・
     影なし・床なし」を入れる
   - 5秒（120コマ前後）あれば、歩行なら3〜4周期入ります

③ 透過する
   - 平らな下地なので、下地（【背景色】）との色の距離でアルファを作る
   - 縁に残った下地の色を計算で取り除く（観測色 = a×被写体 + (1-a)×下地 を被写体について解く）
   - 下地のゆらぎ（コマごとに1〜2ずれる）を切り捨てる下限を入れる。
     入れないと画面全体が alpha 0.05 くらいで薄く残ります
   - 確認: 抜いた絵を 白・黒・緑の3色に載せて見せてください。
     白だけだと白いフチが見えません

④ ループ区間を決める ← ここが本番
   - まず「足がいちばん開くコマ」の間隔を測る。これが1歩。1周期＝2歩
   - 次に画像の一致度でも周期を出す（Lコマずらした差の平均が小さいところ）
   - この2つを突き合わせる。食い違ったら、歩数のほうを信じる
   - 理由: 一致度の最小値は、半周期にも倍周期にも転びます。
     半周期で切ると同じ足だけが前に出て、片足で跳ねて見えます
   - 継ぎ目の良さは「繋ぎ目の差 ÷ 普通のコマ送りの差」で見る。1.0前後なら見分けられません

⑤ 1周期を【コマ数】枚にそろえる
   - 決めた1周期の中から、等間隔に【コマ数】枚を選ぶ（「動画のまま全部」なら間引かない）
   - 1周期に入っている動画のコマが【コマ数】より少ないときは、補間で水増しせず、
     実際のコマ数を私に伝えて相談してください
   - 全コマを同じキャンバスサイズ・同じ足元の位置のまま出す（コマごとに切り詰めない）

⑥ 確認して終わる
   - 出力した【コマ数】枚を、間引かずに全部並べた一覧画像を見せてください
   - 顔の向きは原寸で並べて見せてください。縮小した一覧では判定できません。
     複数キャラなら全員が同じ向きか確認します
   - 攻撃やジャンプなど1回で終わる動作は、ループにしないでください。
     「閉じない」と出たらそれが正しい判定です

【出すもの】（すべて【保存先】へ）
- 1周期ぶん【コマ数】枚の透過PNG連番（frame-000.png から）
- 横並びのスプライトシート（PNG）＋ コマ数・1コマの幅と高さ・【fps】 を書いたJSON
- 動きを確認できるもの（【fps】で再生するGIFなど）

役に立ったら、いいね・リポスト・引用リポストをしてもらえると励みになります。うまくいかなかったところを引用で教えてもらえるのも、同じくらい助かります。

② 1枚ずつ描かせる（動画が使えないとき）
参照画像を渡せば、髪飾りの宝石やコートの模様まで保てます。ただし足元と大きさがずれます。少ないコマ数で、あとから位置を合わせる前提なら使えます。


キャラクターの歩行アニメーション用に、連番のPNGを作ってください。
設定画は <ここにパス> にあります。見た目は文章にせず、画像を参照として渡してください。

■ 出力するもの
・1枚に1コマ。4〜8枚。全部おなじキャンバスサイズ（例: 1024 × 1536）
・ファイル名は frame-000.png から連番
・背景は中性グレー（#6E6E6E）の平らな一色。透過にしない
・1枚の中に複数のコマを並べない。番号・枠・説明文を入れない

■ 全コマで固定するもの
・髪、瞳、衣装、装飾、頭身、左右の向き
・カメラの位置、視線の方向、被写体の大きさ、光の向き
・足元の基準線（地面の高さ）と、体の基準点

■ 動きのつけ方
・「接地 → 沈み → 通過 → 上昇」を、左右の足で一巡させる
・最後のコマに1コマ目と同じ絵を置かない（ループで重なるため）

■ 気をつけること
・頭のてっぺんと足先が切れないよう、余白を残す
・床の影、発光、半透明のふちは入れない
・途中で顔や服が変わったコマ、欠けた手足は、そのコマを描き直す

■ 出したあとに必ずやること
・全コマの「足元のY座標」と「頭頂から足先までの高さ」を測って並べてください
・足元が8px以上ずれているコマ、高さが5%以上違うコマを教えてください
  （そのままでは歩行になりません。位置合わせか描き直しが要ります）


上の指示文で4コマ作って測った結果が、比較表の右の列です。「全コマで足元をそろえて」と書いても、そろいません。だから最後に測る工程を足してあります。





使うエージェントによって、必要なものが違います
  • Codex / ChatGPT — 画像生成は組み込まれています。②はそのまま渡せます。①の動画生成は入っていないので、動画のサービスを別に用意してください。
  • Claude Code — それ自体には画像も動画も作る機能がありません。Codexを呼び出せるようにするか、画像生成サービスへの接続（OpenRouterなどの連携）を先に用意してください。そのうえで指示文を渡します。
①で使える動画生成は、画像から動画を作れるもの（image-to-video）なら何でもかまいません。ローカルで動かす構成でも同じ手順です。ポーズを固定して1枚ずつ描く方法（ControlNetなど）もありますが、こちらは試していません。




Pixel Refinerと、どこが同じ？
公開されているMIT版PixelRefinerの画像処理エンジンを使用しています。単画像では上流の自動分類・格子推定・エッジを考慮した縮小を利用。連番では当ツールが1コマ目の解像度を固定し、共通の切り抜きと減色を追加します。公式サイトの全設定・全候補UIの再現ではなく、設定・バージョンによって仕上がりは異なります。
細かい装飾を保護するため、小さな孤立領域の自動除去はこの版では無効です。透かしの除去も行いません。

PNG・APNG・GIFの違いと、できることの限界
PNGとAPNGはフルカラーを保存できます。GIFは最大256色（透明色を含む）と10ms単位の時間制約があるため、色と速度が変わる場合があります。ゲーム素材はPNGシート、見た目の確認はAPNGが適しています。
このツールは、1枚から新しいポーズを生成するものではありません。顔・衣装・手足の整合性や足の接地は入力の品質に依存します。自動背景透過は背景と服の色が近い場合に欠けることがあります。出力を見て、背景の維持や元画像の修正を選んでください。
変換はこのページの中だけで行われます。画像がサーバーへ送られることはありません。結果はブラウザに一時保存され、直近5件まで再表示できます。閲覧データを消すと一緒に消えるので、必要なものは書き出して保存してください。
